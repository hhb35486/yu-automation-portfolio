# Excel / CSV Cleaner Post-Deploy Validation

## Purpose

This document defines the post-deploy validation plan for the Excel / CSV cleaner demo.

This is not a formal product launch. It is a 14-day low-risk observation plan for a public portfolio demo that uses synthetic sample data only.

The goal is to learn whether the "report table cleaner" positioning creates useful conversations. The goal is not to add features, build SaaS, charge money, run ads, add analytics, or process real files.

## Validation Window

14 days.

Suggested window:

- Day 1: confirm the public demo is still working.
- Days 2-13: manually log any meaningful reactions.
- Day 14: review the log and decide whether to keep, pause, or test a different owned asset.

## What To Observe

Only observe low-risk signals:

- Whether someone opens the demo
- Whether someone asks about this tool
- Whether someone clicks contact or sends a message
- Whether someone says they want to clean a similar table
- Whether someone asks to send real customer data
- Whether someone does not understand the positioning
- Whether someone treats it only as a free small utility and does not want to discuss further

## Manual Observation Only

Do not add analytics, tracking, or third-party tools in this phase.

Use manual notes only. This keeps the validation lightweight and avoids adding instrumentation before the demo has shown clear demand.

## Success Signals

- Someone proactively asks about a similar tool
- Someone clearly describes a table-cleaning pain
- Someone clicks contact or sends a message
- Someone asks whether a similar workflow can be customized
- Someone reacts to the "report table cleaner" positioning

## Weak Signals

- Someone only views the demo and says nothing
- Someone only downloads the sample
- Someone thinks the feature is ordinary
- The question is too broad and has no clear scenario
- Someone only wants free usage and does not want to discuss the workflow

## Stop / Pivot Rules

If there is no inquiry and no clearly described pain within 14 days:

- Do not add features
- Do not build SaaS
- Do not charge money
- Do not run ads
- Return to the owned asset matrix and review the PDF extractor backup

If someone says the demo is hard to understand:

- Fix the explanation and before / after presentation first
- Do not add features just to compensate for unclear messaging
- Keep the sample simple enough to understand in a few seconds

If someone asks to process sensitive data:

- Do not accept real data
- Reply that the discussion must use synthetic or de-identified examples
- It is acceptable to discuss a local or internal tool concept
- Do not process the actual file in this public demo flow

## Day-14 Review Questions

- Did anyone describe a concrete table-cleaning problem?
- Did anyone use the contact path?
- Did anyone understand the report-table-cleaner positioning?
- Did anyone ask for unsafe data handling?
- Is the next best step a copy tweak, a different demo, or pausing this line?

## Decision Options

- Keep: the demo generated clear and safe inquiry signals.
- Tune copy later: the demo created mild interest but the positioning was unclear.
- Consider next demo: the demo was understood but did not create useful conversations.
- Pause: the demo created no meaningful signals after 14 days.
- Reject sensitive data path: interest exists, but requests depend on unsafe data handling.
